# ユーザーストーリー評価 — prism

- **Decision: Execute**
- **Rationale**: デモ UI に本物のユーザー向けフロー(開始→許可→調整→停止、エラー復帰)があり、受け入れ条件を FR/NFR に紐づけて明文化する価値がある。ペルソナが 1 名でも「聴きながら合わせ込む」という中核体験は行動記述が最も明瞭。
- **Factors considered**: ユーザー向け UI あり / ペルソナ 1 名 / ビジネスロジックは単純 / チーム間調整なし → 実行するがストーリー数は最小(6 本)に圧縮。
- **Key areas**: 合わせ込み体験(スライダー操作と即時反映)、エラー復帰(マイク拒否)、数値検証の完了条件。

視点別評価(mob 支援視点、統合記載):

- UX(design): フローは 1 画面・最短 3 操作。エラー状態からの復帰導線が唯一の分岐で US に含めるべき → US1.3 に反映。
- 実装容易性(developer): ストーリーは Unit 境界(コア/検証/デモ)と 1:1 に割れるため見積もり容易。技術ストーリー 2 本(US2.x)で DSP・検証を扱う。
- テスト容易性(quality): 受け入れ条件はすべて数値または UI 状態で判定可能。NFR は US2.x の受け入れ条件に吸収し、traceability.json で全数マッピングする。
