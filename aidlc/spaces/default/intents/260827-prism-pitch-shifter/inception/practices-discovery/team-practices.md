# チーム慣行 — prism (Prism Earring)

## Way of Working

トランクベース開発。main 一本を保ち、Construction の作業単位(Bolt)は短命ワークツリーで進めて完了時に squash して main へ 1 コミットで載せる。長命ブランチは作らない。個人開発だが、監査証跡と作業単位がコミットに対応して残るためこの運用を維持する。[Q1]

## Walking Skeleton

スケルトン儀式は省略する。本プロジェクトは Unit 3 つの一直線(DSP コア → オフライン検証 → Web デモ)で全体が既に「薄い一気通貫」規模のため、専用の先行スライスを設けず U1 から通常どおり構築する。[Q2]

## Testing Posture

- **Methodology**: test-after
- **Ordering**: 各 Unit を実装した後、その Unit に対応するオフライン数値検証テストを書いて実行し、緑を確認してから次の Unit に進む。

補足(custom 床): org 既定の 80% 行カバレッジ床は本件では適用しない。代わりに **4 つの数値検証(ピッチ精度 0.95±0.5% @ 110/440/3520 Hz、処理部遅延 ≤10ms、グリッチゼロ、CPU 余裕)がすべて緑であることをマージ条件**とする。テストは外部依存ゼロ(clang++ のみでビルド・実行)。検証側の FFT は自前実装(音声経路には FFT を使わない)。[Q3]

## Deployment

デプロイなし。Web デモは静的ファイルをローカルで開くか、開発機のローカル HTTP サーバで配信し、Pixel からは同一 LAN でアクセスする。ホスティング公開は行わない(将来配布を検討する際に、医療機器規制の確認とセットで判断する)。[Q4]

## Code Style

- 言語: C++17。LLVM 風 4 スペースインデント。フォーマッタ設定ファイルは置かない。
- 命名: 名前空間 `prism`、コアクラス `prism::PitchShifter`。コード中の表記は `prism` / `PrismEarring`(`Prism Earring` は使わない)。
- コンパイラ警告 `-Wall -Wextra` をエラー扱い(`-Werror`)。
- リアルタイム経路(オーディオコールバック)の禁止事項を規約として明文化: ヒープ確保/解放・ロック・ファイル I/O・ログ出力・システムコール・例外。パラメータ受け渡しは `std::atomic`。バッファは初期化時確保・固定長。
- レイヤ分離: DSP コア(純 C++、他依存なし)/ 検証ハーネス / プラットフォーム接着層(WASM ブリッジ・AudioWorklet JS)を厳密に分ける。[Q5]
