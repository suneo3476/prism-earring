# リスクと順序付けの根拠 — prism

## 順序: B1 → B2 → B3(依存順 = リスク先行)

- 2.7 の DAG では u2 と u3 は並行可能だが、**u3 の開始条件に u2 の全検証緑を課す**経済判断を採る。理由: デモを先に作ってもコアの数値品質(ピッチ精度・遅延)が未確認では聴感評価の解釈ができない。検証緑後なら、デモで聞こえる問題はブラウザ層に切り分けられる。[Q1] [Q3]
- 位相的順序からの逸脱はなし(依存順そのもの)。

## 先頭リスクの潰し方

| リスク | 判明タイミング | 対応 |
|---|---|---|
| ピッチ精度 0.95±0.5% 不合格 | B2 の検定 | 補間を線形→4 点 Hermite に切替(D-02。コアは差し替え可能な構造) |
| 処理部遅延 >10ms | B2 の検定 | crossfade_ms 既定値の見直し(窓長が支配項。式は契約 1 に明記) |
| Emscripten 導入不調 | B3 冒頭 | AudioWorklet 内 JS 実装へ切替(raid-log R-03。アルゴリズム同一) |
